## A. Research + 18–20 блоков  
**Модель: Claude Opus (thinking high)**  
**Когда:** первым делом, до макета

```
Ты делаешь исследование и копирайт для лендинга RUBIN.

Обязательно прочитай:
@docs/RUBIN-LANDING-CONTEXT.md

Источники (все три, не пропускай):
1) Статья: https://decenter.org/rubin/ — особое внимание блоку про разработчиков, API/White Label, AI/MCP, RUB1, общую ликвидность.
2) Telegram export: @telegram_export/result.json — посты с 25 апреля (первое упоминание RUBIN и далее). Выпиши цитаты/факты, пригодные для hero и секций. Если файл большой — стримь/фильтруй по дате и ключевым словам, не грузи всё в ответ.
3) Структура: https://rubx.ru/ — сравни с фактами из статьи и TG: что пересекается, чего у RUBIN больше (L1, DEX, девы). Не копируй бренд RUBx.

Аудитория: в основном квалифицированные инвесторы/трейдеры с опытом крипты; новички интересны, но их блоки — только в конце лендинга.

Задача:
1. Краткий бриф продукта (10–15 буллетов, только проверяемые факты).
2. Таблица пересечений DeCenter ↔ TG ↔ rubx.ru.
3. Список ровно 18–20 блоков лендинга в порядке скролла.
   Для каждого блока:
   - id / название секции
   - для кого (QI / девы / новички)
   - H1/H2 (русский)
   - lead 1–2 предложения
   - 3–6 буллетов или карточек
   - тип медиа-плейсхолдера (подпись для серого прямоугольника)
   - CTA если есть
4. Сохрани результат в docs/RUBIN-LANDING-BLOCKS.md
5. Не придумывай метрики (объёмы, TVL, число пользователей), которых нет в источниках — помечай TBD.

Не делай Figma и не пиши HTML. Только исследование и тексты.
```

## B. Макет Figma 1728 (Sana-паттерны)  
**Модель: Composer или Claude Sonnet**  
**Когда:** после появления `docs/RUBIN-LANDING-BLOCKS.md`  
**Чат:** можно этот или новый

```
Собираем макет лендинга RUBIN в Figma через плагин.

Контекст:
@docs/RUBIN-LANDING-CONTEXT.md
@docs/RUBIN-LANDING-BLOCKS.md

Дизайн-референс (ритм/секции Sana):
https://www.figma.com/design/qP71JDsFhe8TG9zQujUcF3/RUBIN?node-id=156-68231

Жёсткие требования:
— ширина артборда 1728 (не 1440)
— шрифт Google Sans
— вместо картинок: серые прямоугольники с подписью внутри (что должно быть: UI терминала / схема L1 / люди / и т.д.)
— визуальные паттерны как у Sana (hero, dual, slider, metrics, split, tabs, grid, quotes, partnership, steps, CTA) — НЕ меняй отступы, радиусы, размеры шрифтов паттернов без моего явного разрешения
— 17 секций строго по RUBIN-LANDING-BLOCKS.md §5, колонка «v1»
— блоки 09 (White Label), 10 (Разработчикам) и 12 (RUB1) в макет НЕ берём — они помечены «Не в макет v1»
— фокус B2C: никаких dev/B2B-вкраплений в оставшихся блоках (навигация, CTA, карточки, футер)
— новички только в конце
— тексты на русском из BLOCKS; бренд RUBIN
— никаких упоминаний референсов: rubx / RUBx / rubx.ru, Sana / Sana Labs / sanalabs.com и любых других сайтов-референсов — ни в текстах, ни в именах слоёв, страниц, артбордов, переменных и комментариев. Картинки с CDN референсов не подключай — только серые плейсхолдеры и утверждённые фото

Реализация:
— билдер лежит в figma-landing-builder/code.js, страница «RUBIN · Landing 1728»
— атомы ставить инстансами компонентов со страницы «DS · RUBIN components» (кнопки, карточки, стат-блоки, FAQ-строки, шаги, таймлайн, hero); секции собирать авто-лейаутами поверх
— новые компоненты добавлять только в figma-ds-plugin/code.js и помечать «extension»
— не ломай существующие референс-клоны на отдельных страницах
— после правок скажи, как перезапустить плагин

Не деплой на GitHub. Не создавай PR.
```

### F1 — Инвентаризация DS (токены + список компонентов)  
**Модель: Claude Opus** · **Новый чат**

```
Нужна design system Sana (Sana Labs) для переноса в Figma как UI-kit.

Контекст проекта: @docs/RUBIN-LANDING-CONTEXT.md

Источники (пройди все доступные):
1) https://sanalabs.com/ и ключевые внутренние страницы (Products, Pricing и т.д.) — через браузер: кнопки, инпуты, карточки, табы, нав, футер, пиллы, цитаты, прайсинг-карточки, лого-стрипы.
2) https://brand.sanalabs.com/ — логотипы и brand guidelines.
3) Наш эталон в Figma (уже есть клон лендинга): файл RUBIN, нода Sana layout node-id=156-68231 — сверь ритм с live-сайтом.
4) При необходимости CSS/computed styles со страницы (цвет, radius, font-size, padding, shadow).

Задача — сохрани в docs/SANA-DESIGN-SYSTEM.md:
1. Foundations: цвета (hex + роль), типографика (семейства/замены: Sana Sans → Google Sans/Inter в Figma), размеры type scale, spacing scale, radii, shadows, grid (desktop 1728 и/или 1440 как на сайте).
2. Полный инвентарь компонентов (чеклист): Button (primary/secondary/ghost + sizes), Link, Input, Textarea, Select, Checkbox, Nav item, Pill/Tab, Card variants, Quote card, Pricing card, Logo cell, CTA banner, Footer columns, Media frame, Badge, Divider… — всё что реально есть на сайте.
3. Для каждого компонента: состояния (default/hover/disabled если видно), размеры (h, padding, radius, font), варианты, описание автолейаута.
4. Чего на сайте НЕТ (не выдумывать «полный Material»).
5. Маппинг: «компонент Sana → как назвать в Figma».

Не создавай компоненты в Figma в этом чате. Только документ-спека.
Не пушь в GitHub.
```

### F2 — Сборка UI-kit в Figma  
**Модель: Composer или Claude Sonnet** · **Новый чат (после F1)**  
Нужен открытый файл Figma + плагин Development / MCP Figma.

```
Собираем UI-kit Sana в Figma по спеке.

Спека: @docs/SANA-DESIGN-SYSTEM.md
Контекст: @docs/RUBIN-LANDING-CONTEXT.md

Сделай в файле RUBIN (qP71JDsFhe8TG9zQujUcF3) отдельную страницу:
«DS · Sana components»

На странице:
1. Foundations — Color styles / Text styles (или фреймы-сэмплы, если styles недоступны из плагина), spacing, radius.
2. Компоненты как Figma Components (не просто фреймы): Buttons, Inputs, Cards, Pills/Tabs, Nav, Quote, Pricing, CTA, Logo cell, Media placeholder и остальные из спеки.
3. Для каждого — варианты через Properties (variant) где уместно: size / state / type.
4. Подписи и orderly layout: секции Foundations → Actions → Forms → Navigation → Cards → Feedback → Layout.
5. Шрифт: Google Sans (если нет Sana Sans). Не подменяй визуальные размеры из спеки.
6. Реализация: единственный источник DS — figma-ds-plugin/code.js (плагин «RUBIN DS», страница «DS · RUBIN components»). Не ломай существующие артборды лендинга.

Критерий готовности: по спеке закрыт чеклист компонентов; на странице DS можно инстансить кнопки/карточки в макет RUBIN.

Не деплой на GitHub. Спроси перед любым push.
```

### Как запускать DS

1. **Новый чат → Opus → F1** (можно параллельно с промптом A).  
2. Проверь `docs/SANA-DESIGN-SYSTEM.md`.  
3. **Новый чат → Composer → F2** (открой Figma на файле RUBIN).  
4. Потом промпт **B** (лендинг) может опираться на готовые компоненты DS.

## Как запускать по шагам (лендинг)

1. Новый чат → **Opus** → промпт **A**  
2. Проверь `docs/RUBIN-LANDING-BLOCKS.md`, при необходимости **E**  
3. Параллельно: **Opus → F1**, затем **Composer → F2** (design system)  
4. Этот или новый чат → **Composer** → промпт **B** → перезапуск Figma-плагина  
5. После ок по макету → промпт **C**  
6. Когда скажешь «можно на GitHub» → промпт **D**
