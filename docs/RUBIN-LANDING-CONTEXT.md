# RUBIN Landing — контекст проекта

Рабочий документ для AI-агентов и людей. Цель: лендинг криптобиржи / финансовой инфраструктуры **RUBIN** → макет Figma → вёрстка → GitHub Pages.

Дата сборки контекста: август 2026.

---

## 1. Продукт (что продаём)

**RUBIN** — не «ещё одна витрина поверх чужого движка», а **собственный L1-блокчейн (EVM)** + первая точка входа — **DEX бессрочных фьючерсов**.

Ключевая идея: общая финансовая инфраструктура, на которой банки, брокеры, финтех и независимые разработчики запускают свои продукты.

### Стек и контроль
- Собственный L1 (mainnet, EVM-compatible)
- Свой торговый движок, исполнение и расчёт сделок
- API / White Label / SDK / UI Builder
- Инфраструктура смарт-контрактов
- Инструменты для запуска финсервисов

### Биржа (первый продукт)
- DEX perpetual futures
- Подключение ETH-кошелька
- BTC, ETH, HYPE и др., плечо до **×10**
- Показывает, что инфра уже обслуживает реальные сделки

### Для бизнеса и разработчиков (важный блок статьи)
- White Label / API — запуск биржи, брокера, терминала под своим брендом
- Общая ликвидность сети (не десятки закрытых стаканов)
- Открытый API: терминалы, мобайл, копитрейдинг, алго, аналитика, сигналы, риск-менеджмент
- Упрощённый SDK (ордера, позиции, балансы, маркет-данные)
- UI Builder — быстрее собрать торговый UI
- **AI-агенты через MCP**: чтение стакана/свечей, балансы, ордера; чат/голос + обычный терминал
- Программируемые сделки, смарт-контракты (факторинг, B2B-расчёты и т.п.)
- **RUB1** — расчётный рублёвый контур внутри инфраструктуры (не замена рубля / банков)

### Команда
- Основатели/разработчики с опытом высоконагруженных сервисов Яндекса
- Финтех, банковская инфра, регулирование

Источник фактов о продукте: [decenter.org/rubin](https://decenter.org/rubin/)

## 4. Дизайн и макет (жёсткие правила)

| Параметр | Значение |
|----------|----------|
| Ширина артборда | **1728** |
| Шрифт | **Google Sans** (если нет в Figma — ближайший доступный + пометка) |
| Интерлиньяж | Задаём **процентом** от кегля, а не пикселями: в шкале это коэффициенты 1.1 / 1.2 / 1.4 / 1.5, и в пикселях они дают дроби (16 × 1.4 = 22.4). В коде плагинов `lh` по-прежнему пишем в пикселях — хелпер `T` сам переводит в проценты |
| Медиа | **Серые прямоугольники** с подписью — во всех блоках, включая hero (16:9). Фото добавим позже, отдельным шагом |
| Сюжеты медиа | **Сначала люди, потом интерфейсы.** Hero — люди. В `02` — один общий кадр терминала. Детальные UI — с `05`. В `03` — текстурные фоны карточек |
| Стиль | Паттерны Sana (hero, dual cards, feature slider, metrics, split, tabs, integrations grid, quotes, partnership, logos, pricing/steps, CTA) |
| Визуал | **Не менять** отступы/типографику/радиусы Sana-паттернов без прямого указания пользователя |
| Фон карточек | Карточка всегда контрастирует с фоном секции: белая секция — песочные карточки, песочная секция — белые. Дефолтная заливка компонента может совпасть с фоном (у `Card / Stat` это #F7F7F7 против песочного #F6F5F4) — тогда перекрываем заливку на инстансе |
| Кнопки | На странице — `Button · Size=Large` (h 56, боковые отступы 24, текст 16/22.4). В закреплённой шапке остаётся `Size=Header` (h 36). `Size=Default` (h 38) на лендинге не используем. Внимание: в `Section / Hero` кнопки вшиты фреймами и от компонента `Button` не наследуются — размер там правится в самом hero |
| Язык копирайта | **Русский** |
| Цвет текста | Лиды под заголовками и описания в карточках, шагах, CTA и ответах FAQ — **чёрные**, без прозрачности. Серыми остаются только служебные подписи: кикеры, подписи к медиа, сноски, дисклеймеры и футер |
| CTA (черновик) | «Начать торговлю» / «Документация» / «API для разработчиков» — уточнить после ресёрча TG |

### Плагины Figma в репо

| Папка | Плагин | Что делает |
|---|---|---|
| [`figma-ds-plugin/`](../figma-ds-plugin/) | **RUBIN DS** | Страница `DS · RUBIN components` — ~50 компонентов UI-kit. Единственный источник DS, правки только сюда |
| [`figma-landing-builder/`](../figma-landing-builder/) | **RUBIN Landing** | Страница `RUBIN · Landing 1728` — 17 секций из инстансов DS |
| [`figma-landing-plugin/`](../figma-landing-plugin/) | RUBIN Landing Generator | Референс-клоны на отдельных страницах, ориентир по ритму секций |

Порядок запуска: сначала **RUBIN DS**, затем **RUBIN Landing** — билдер берёт компоненты только со страницы `DS · RUBIN components` и падает с подсказкой, если её нет. Другие страницы, начинающиеся с `DS ·` (остатки прошлых прогонов и переименований), игнорируются, о них выводится предупреждение — такие страницы надо удалять, иначе легко решить, что правка в DS «не доехала».

Атомы (кнопки, карточки, стат-блоки, FAQ-строки, шаги, таймлайн, hero) ставятся **инстансами** DS, секции собираются авто-лейаутами поверх. Правка в компоненте протягивается в макет. Медиа — серые плейсхолдеры с подписью, картинки референсов не подключаем.

Компоненты-расширения, которых нет на референсе: `Section / Hero`, `Steps / Card`, `Timeline / Row 6`.

## 7. Ограничения и запреты

- Не обещать доходность, «лёгкие деньги», гарантии прибыли.
- Не выдавать RUBx за продукт RUBIN; rubx.ru — только структура повествования.
- **Референсы не упоминаются в продукте.** `rubx` / `RUBx` / `rubx.ru`, `Sana` / `Sana Labs` / `sanalabs.com` и любой другой сайт-референс не должны встречаться нигде в том, что видит пользователь или что попадает в репозиторий сайта: тексты и имена слоёв/страниц/артбордов в Figma, HTML/CSS/JS, имена классов и переменных, комментарии, `alt`, meta-теги, имена файлов и ассетов. Медиа референсов (картинки с их CDN) на наш лендинг не тянем — только серые плейсхолдеры и утверждённые фото. Названия референсов допустимы **только** во внутренних файлах `docs/` как указание на источник.
- Не пушить в GitHub / не создавать PR без подтверждения пользователя.
- Не менять визуал Sana-паттернов (отступы, шрифты, цвета) без прямого запроса.
- Факты о продукте — только из DeCenter / TG / официальных материалов; выдуманные метрики запрещены (плейсхолдеры вида «N рынков» — помечать как TBD).

## 9. Definition of Done

1. Утверждён список 18–20 блоков с текстами.  
2. В Figma собран макет шириной 1728, Google Sans, серые медиа с подписями.  
3. Вёрстка 1:1 по смыслу секций, адаптив минимум desktop + mobile.  
4. Сайт на GitHub Pages (после разрешения).  
5. Новички — только в нижней трети лендинга.
